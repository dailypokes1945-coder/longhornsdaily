The site itself (GitHub repo, Cloudflare Pages, KV content, the domain, the editor login) belongs to the owner's own GitHub and Cloudflare accounts, so none of it moves. Only three things were set up inside the Claude account:

1. **The GitHub connection** Claude uses to push to this repo.
2. **The scheduled "Longhorns Daily morning update" task** (every day at 5:13 AM Central), which rewrites `public/auto.json`, `public/history.json` and `public/rundowns.json`.
3. **The scheduled "Longhorns Daily midday + evening update" task** (every day at 11:53 AM and 6:53 PM Central), which only merges new stories, the ticker and expirations into `public/auto.json`.

### Morning update prompt (copy exactly)

```

REPO: GitHub dailypokes1945-coder/longhornsdaily (branch main). Attach it with add_repo (owner dailypokes1945-coder, repo longhornsdaily, access push) and clone it. If https://longhornsdaily.com/api/site doesn't load yet (site not connected), work from the repo's own files (functions/_seed.js holds the starting owner headlines, public/overrides.json any extras) and mention it in the report.

1) TICKER -> the "ticker" field of public/auto.json
- The ticker is the one line under the logo listing the NEXT 3 Texas athletic events (any sport, men's or women's: football, basketball, volleyball, baseball, softball, track and field, swimming and diving, etc.), counting from today in Central time. Drop anything that has already finished. Example format (one line, ★ between events, keep it under ~180 characters):

Include current AP/CFP rank (No. X) for Texas or the opponent when they're ranked, the time (Central) and TV if known, and "at" for road games, "vs." for home/neutral. Keep owner flair that is still accurate by reading the current ticker on https://longhornsdaily.com/api/site ("ticker") and the existing auto.json ticker.

Joining the texts with " ★ " must give exactly the "ticker" string. Add "tickets" only for a ticketed Texas event (a game, match, dual or meet, home or away) whose StubHub event page you found through web search: a www.stubhub.com URL for that exact event (opponent and date match), usually containing "/event/<number>". Use the plain StubHub URL with no tracking code; the site adds the owner's affiliate link and disclosure. If a slot has two events, use the bigger one's page. If you can't find the exact page, leave "tickets" out; never guess or build a URL.

2) EXPIRE STALE STORIES -> public/auto.json "expired"

A story is EXPIRED when it is a preview, prediction, odds/betting line, "how to watch", kick/tip time, uniform reveal, matchup/bout preview, or other info about a specific game, match or dual that has ALREADY BEEN PLAYED (as of this morning, Central time). Examples: "Horns 20-point favorites vs. Arkansas" after that game is over; a Southern Utah preview after the Southern Utah game. Stories that stay relevant (recruiting, coaching news, features, season-long stories, results/recaps) are NOT expired.
